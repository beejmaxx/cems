# Repository housekeeping

- Keep the current whitepaper PDF and Typst source at the repository root, linked from README.md.
- Put generated previews, test logs and render scratch files under ignored `output/` or an external temporary directory. Keep task outputs together and reuse their directory on follow-up passes.
- Before finishing a task, review newly created files, consolidate its scratch material, and update links to the current deliverables. Avoid creating overlapping guides or new dated directories for every pass.
- Preserve unknown files and existing user changes. Before relocating retained artifacts, check references and verify their bytes. Do not delete models, inputs, prepared plans, campaign state, receipts, coverage or pinned binaries as routine housekeeping.
- Personal models and recovery evidence belong in an external private workspace and must never enter this repository's source or Git history.
